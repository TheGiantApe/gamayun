# gamayun-site

Static, zero-dependency web tools site. See `_src/` for the build system.

## Structure
- `_src/templates/base.html` — the one shared page shell (header/nav/footer/mascot deck).
- `_src/content/*.html` — per-page content fragments (just what goes in the center viewport).
- `_src/build.py` — assembles template + fragments into the final static pages. Run with `python3 _src/build.py` from the repo root. Stdlib only, no dependencies to install.
- `css/`, `js/`, `index.html`, `pages/*.html` — the actual shipped site. Generated by build.py; don't hand-edit the generated HTML files directly, edit the source in `_src/` and rebuild.
- `js/gama-core.js` — G.A.M.A.'s state engine (mascot face/dialogue, log ticker, clock). Every tool script calls `GAMA.say()` / `GAMA.log()`.
- `js/tool-*.js` — one file per tool's actual logic. Pure functions, no framework, easy to unit-test with plain `node -e`.

## Adding a new page
1. Write the fragment in `_src/content/yourpage.html` (just the inner content, matching the pattern of existing fragments).
2. Add one line to the `PAGES` list in `_src/build.py`.
3. Run `python3 _src/build.py`.

## Adding a new tool
1. Write `js/tool-yourtool.js` — pure logic function(s) + one `execute*()` function wired to a button, calling `GAMA.say()`/`GAMA.log()` on state changes.
2. Test the logic directly: `node -e 'eval(require("fs").readFileSync("js/tool-yourtool.js","utf8")); console.log(yourFunction(...))'` — no browser needed to verify the logic before it's wired to a page.
3. Write the content fragment + register it per above, load the tool's JS via the `extra_js` field in `_src/build.py`.

## Local preview
`python3 -m http.server 8000` from the repo root, then open `localhost:8000`.
